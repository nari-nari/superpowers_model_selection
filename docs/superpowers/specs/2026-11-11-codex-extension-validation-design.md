# Codex拡張での独立モデルルーティング検証仕様

- 作成日: 2026-11-11（Asia/Tokyo）
- 状態: 独立した実装者視点のレビュー済み仕様案。ユーザーが2026-11-11に本仕様・計画に沿う実装と検証を承認。拡張での上限付き試験・解除を実施して記録済み。provider実効・実費など未検証事項は検証記録へ分離した。
- 基準: 管理リポジトリ `e29b793bd417b7413f01a5171d4e212d90d03279`。
- 対象: このPCのVS Codeで動くOpenAI Codex拡張。識別子は `codex-vscode`。
- 契約: ユーザー回答によりChatGPTアカウントでログイン。後続のユーザー回答によりPlus。追加クレジットの利用有無・speed・組織制約は未確認。

## 1. 目的と承認範囲

ユーザーは、先に提示した「隔離した検証用プロジェクトで読み込み・判断を確認し、Codex用の指定手順と料金根拠を整えて2モデルを比較する」方針での検証を依頼した。本書はその合格条件と変更範囲を具体化する。仕様書・計画の作成を先行し、未提示の詳細まで承認済みとは扱わない。

公式Superpowers本体を無改変で利用し、独立レイヤーがCodex拡張で読み込まれ、必要能力を満たすモデルを選択して正式に指定できるかを調べる。消費量と料金が観測できる範囲も明らかにする。Copilot各環境の未検証状態は独立して保持する。

## 2. 現状と方式

現行の入口は `overlay/instructions/model-routing.md`、選択スキルは `overlay/skills/model-selection/`。環境ガイドとカタログはCopilot向けで、`decision-record.md` のクレジット換算もCopilot契約専用。単にCodexの認識先へコピーすると、料金・環境・候補の参照が一致しない。

ローカルにはCodex拡張のファイルが2版存在する（`26.51007.21434`、`26.51021.22027`）。稼働中の版、ログイン先プラン、拡張セッションのツールは未確認。PATH上に `codex` はあるが `code`・`copilot` は見つからなかった。ファイルの存在は拡張の稼働証拠にならず、`code` 不在もGUI利用不可の証拠にならない。

| 方式 | 利点 | 制約 | 判断 |
| --- | --- | --- | --- |
| 隔離プロジェクトに独立レイヤーを配置して拡張で試験 | 現行構成を再利用し、既存設定への影響を限定できる | 拡張側で新規会話と実効値確認が必要 | ユーザーが選んだ既提示の方針。本書で具体化 |
| CLIだけで代理試験 | 自動化しやすい | 拡張の読込・UI・実効情報を証明できない | 補助確認に限定 |
| 全体設定へ直ちに常設導入 | 全プロジェクトで使える | 原因の切り分けと解除確認が難しくなる | 今回は行わない |

## 3. 不変条件

- 公式Superpowers本体・プラグインキャッシュを変更しない。実際の版・取得元を記録し、既存基準v7.0.2との相違は互換性未確認として扱う。
- 個人のCodex設定、既存スキル、Copilot設定、MCP、親モデルの既定値は変更しない。新規の隔離プロジェクト内だけに所有ファイルを置く。
- Copilotカタログの料金・利用可否・モデルIDをCodexへ流用しない。既存のCopilot候補JSONと算術F01～F05を保持する。
- 必要能力、レビューの独立性、本体の修正上限を維持する。通常最終レビューを最高価格モデルへ固定しない。
- 親だけが選択する。子へ料金表全体を渡さず、再委譲を要求しない。
- 実効モデルの自己申告、指示中のモデル名、親モデルの変更、別CLIセッションを、子モデル指定の証拠にしない。
- 観測できない値は `unknown`、未実施・証拠不足の受入は `unverified`。既存3環境の実機受入へ結果を転記しない。
- 試験は同時1子、各依頼は小さな読み取り中心とし、自動反復しない。数値予算は明示指定時だけ適用する。

## 5. 課金契約と候補

ChatGPTでのログインとAPI従量課金は別契約として扱う。当初は `chatgpt-plan-unknown` で開始する設計だったが、ユーザーがPlusと確認したため `chatgpt-plus-bucket-unknown` を使用する。アカウント画面と公式根拠からプラン・適用条件が確認できた時点で具体化する。ログイン方式だけでプラン名・単価・残量を補完しない。API価格やCopilotの「1 credit = 0.01 USD」を代入しない。

比較に使える単位は、その契約で確認した `codex-credit`、`USD`、または公式に定義された利用量とする。トークン数、所要時間、残枠表示は補助指標であり、根拠なく金額・クレジットへ変換しない。入出力、推論、キャッシュ、必須レビュー、引き継ぎ・1回修正の経路を既存方針に沿って考慮する。料金鮮度は30日、コンテキストの余裕は20%、代表候補は最大3件を維持する。

候補は当該拡張・アカウントが利用できる正確な2 IDを確認してから選ぶ。具体名を本書では固定しない。能力根拠、同じ小作業を実施できる権限、容量、対応する推論設定を確認する。料金がない候補を安いと判定しない。

料金根拠が得られない場合は費用選択を保留する。一方、明示的に固定したモデルを使う「指定経路の能力試験」は費用最適化と分離して実施できる。これは一般作業に無価格候補を選ぶ例外ではない。見積・費用受入はunknown／unverifiedのまま残す。

## 6. 隔離配置と実機操作

実装時に `using-git-worktrees` の手順で管理変更を隔離する。試験プロジェクトはさらに `/private/tmp` 配下の新規ディレクトリに置き、既存リポジトリへのユーザー変更と混在させない。実体パスはローカル記録だけに保存する。

試験用プロジェクトには `AGENTS.md` の共通入口と確認済みbinding、`.agents/skills/model-selection/` の全資料、単独で読める導入・解除手順、`fixture.txt` を置く。fixtureは `routing-fixture: codex-extension-v1` の1行。公式本体は既存の正規導入を確認して利用し、別版を自動インストールしない。同名重複は取得元を識別して試験の有効ソースを確認し、未所有ファイルを削除しない。

拡張に正式な呼出し引数があればその指定を使用する。なければ、当該版で利用を確認したプロジェクト内 `.codex/agents/` のモデル固定workerを検討する。modelと推論設定は実スキーマ・対応値で確認する。定義ファイルの作成だけで適用成功としない。経路がなければその試験を保留し、親変更・CLI起動で代用しない。

このチャットのツールやCLIログは、拡張自身の会話・子スレッド・ネイティブログと出所を分ける。現在の会話が当該拡張と確認できなければ、ユーザーがVS Codeで試験フォルダを開き、新しいCodex会話から提示済みの依頼を実行する。GUI操作機能が使えない場合、必要な操作と採取する最小の非機密情報を一度に案内する。認証ファイル全体、APIキー、無関係な会話ログは収集しない。

## 7. 受入条件

| ID | 試験と合格条件 | 必要な証拠 |
| --- | --- | --- |
| CX01 | 実行中のVS Code・拡張・Codexエンジン・本体版と契約を識別する。取れない欄はunknown | 拡張画面／当該セッションの版情報、契約確認。導入ファイル一覧だけでは不足 |
| CX02 | 新会話で入口・binding・指定のSKILL・方針版が取り込まれ、同名重複の影響を識別できる | 拡張の要求／読込履歴と実ファイル照合 |
| CX03 | 能力と容量を満たす実ID2件を正式に指定し、同一fixtureを読んで正しく返す | 各呼出しの指定引数と独立した実効モデル・推論・容量情報。返答内容だけでは不足 |
| CX04 | 指定拒否・上書き／fallback・未対応推論／contextを成功と誤認しない | 拒否や変換のネイティブ情報。実際に再現できない枝はunverified |
| CX05 | 通常最終レビュー・高リスク・縮小再レビュー・未価格候補について既存方針通り判断する | fixtureを明示した判断試験。実価格やネイティブ適用の証拠とは分離 |
| CX06 | 契約に適用する料金と消費量の単位を確定し、2候補の完了経路見積を比較する | 公式URL・確認日・適用契約・単価／定義。未取得なら費用選択保留 |
| CX07 | 同一fixture・同等条件で利用量を記録し、観測できた範囲だけ比較する | 子呼出し単位の使用量、または帰属範囲が明確な差分。集約残枠しかなければ実費unknown |
| CX08 | 方針適用後も必要レビュー・独立性・修正上限が維持される | 実際の本体ワークフローとの判断比較。判断試験のみなら範囲を明記 |
| CX09 | 配置・更新・解除後に所有部分だけが変更され、既存設定を維持する | 初回と解除後のハッシュ・ファイル集合。解除後の新会話確認 |
| CX10 | 再開時に方針・カタログ版・直前条件を復元し、変更時は再選択する | 既存ケースを拡張の新会話／再開で再現。実際の圧縮未再現なら圧縮受入は未検証 |

CX03は、2候補それぞれの実効モデルを独立確認できる場合にモデル適用をpassとする。推論・容量など個別に観測できない設定は項目別に未検証を残し、「すべての設定を確認済み」としない。正式指定が受理され実効IDが非公開なら、経路確認だけを記録する。

初回は各モデル1回の読み取り試験まで。使用量の観測経路は呼出し前に確認し、差分を使う場合は各呼出しの前後で取得する。CX04は安全な拒否を最大1回だけ再現し、不必要な呼出しを重ねない。CX07でモデル間比較が可能でも、2回の小試験から一般的な節約率や成功率を主張しない。追加の反復比較は観測結果と必要性を示してから計画を更新する。

## 8. 記録と完了判定

共通記録は `case_id`、`runtime`、`surface_evidence`、`extension_version`、`engine_version`、`superpowers_revision`、`routing_revision`、`catalog_revision`、`billing_contract`、`model_requested`／`model_effective`、`effort_requested`／`effort_effective`、`context_requested`／`context_effective`、`estimate_cost`、`actual_cost`、`usage`、`evidence`、`status`。費用は `{value: 数値またはunknown, unit: 単位またはunknown}`、usageは取得元と帰属範囲を添える。秘密・個人パスは共有記録から除く。

各ケースは `pass | fail | unverified`。集約は「準備済み」「判断確認済み」「モデル適用確認済み」「費用比較確認済み」を独立表示し、根拠となるCX番号と未検証欄を併記する。準備だけで「Codex対応完了」と表示しない。全ケースが未検証なら未検証と明記する。

料金不明・実効値非公開・GUIアクセス不可でも、到達した範囲、未確認理由、次に必要な情報を保存して再開可能にする。既存3環境の受入条件を緩和せず、Codexの成功で全体移行完了としない。

## 9. 公式根拠と実装者に任せる事項

OpenAI公式ドキュメントを2026-11-11に取得。仕様に例示された機能と当該インストール版の実機対応を区別し、実行時にも対象ページとライブスキーマを確認する。

- [Build skills](https://learn.chatgpt.com/docs/build-skills): IDE拡張のスキル利用、`.agents/skills` の認識先。
- [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents): IDEでの子スレッド表示、ローカルcustom agentsとモデル設定。
- [IDE settings](https://learn.chatgpt.com/docs/ide/settings): エディター設定とCodex設定の区別。
- [Config basics](https://learn.chatgpt.com/docs/config-file/config-basic): 設定レイヤーとプロジェクトの信頼条件。
- [Pricing](https://learn.chatgpt.com/docs/pricing): 契約と利用枠の確認入口。今回のアカウントの適用価格を確定した証拠ではない。

実装者は、試験ディレクトリ名、非機密ログの保存形式、各対応版の正規導入・観測経路を調査して決める。料金契約、モデルID、対応引数、実効値は裁量で仮定しない。権限制限や既存ファイルとの衝突は該当操作に限定して報告する。
