# 独立モデルルーティングの導入・更新・解除

この手順は手動配置用。実行先は利用するPC／リモート環境であり、管理リポジトリのoverlay自体は自動ロードされない。公式本体と独自機能を別途導入する。実機受入前は試験配置として扱う。

## 1. 配置を決める

| 環境 | 共通入口 | 選択スキル |
| --- | --- | --- |
| VS Code Local・個人 | Agent Customizations → Instructions → Userで作成したプロファイル指示。実際の保存先を記録 | ~/.copilot/skills/model-selection/ |
| VS Code Copilot／CLI・個人 | ~/.copilot/copilot-instructions.md。既存内容に管理ブロックを追加 | ~/.copilot/skills/model-selection/ |
| プロジェクト内 | 対応する.github/copilot-instructions.mdまたはAGENTS.md | .github/skills/model-selection/ |

Localの指示読込設定と選択中harnessを確認する。CLIはエディター設定を継承しない。個人・プロジェクト・プラグイン・管理者提供の全ソースを見て、旧改変本体、公式本体、model-selectionの同名重複を識別する。由来の不明なファイルを消さない。LocalとCLIの入口が別ファイルになる場合、同じ原本から展開し、同一ターゲットへ二重追加しない。

公式本体は公式READMEの該当環境の導入経路を使う。基準はv7.0.2、commit22f0b463e7a5e579904dd6211a520321035526f7。本体のプラグインキャッシュやskillsを編集しない。導入される版が異なる場合は互換性を未検証とし、更新手順で確認する。公式インストール手順が指定版を提供しない場合も、実際の版を偽って基準版と記録しない。

## 2. 既存内容と所有範囲を保存する

配置前に次の情報をローカルの導入記録へ保存する。記録／バックアップはスキル検出先・Git管理対象の外へ置き、認証情報や個人パスを共有文書へ転記しない。

- 方針版2026-11-11.1、料金表版2026-11-10.1、原本コミット、実行環境／クライアント版、本体ソースと版。
- スキル原本、スキル配置先、入口ファイルの正確な絶対パス。
- 入口が元から存在したか、編集前ファイル全体のバイト保存先とSHA-256。既存の改行・BOM・日本語を保持する。UTF-8（UTF-8 BOM可）以外の形式はバイト追記せず、当該環境の対応形式と保全方法を確認できるまで導入を保留する。
- 所有する6スキルファイルの相対パス・SHA-256一覧。未知の既存ファイルは所有物に含めない。
- 入口へ挿入する管理部分全体のバイト保存先・SHA-256。追加した先頭改行も所有部分に含める。
- 必要な場合だけ登録したworkerのパスとSHA-256。既存workerは別管理。

既存のmodel-selectionがあり、過去の所有記録がなければ新規配置を保留し、由来と既存利用を確認する。過去の所有記録がある場合は更新手順で扱う。入口の管理マーカーが片方だけ、2組以上、または記録なしで存在する場合も、追記せず衝突を解消する。

SHA-256の確認例は `shasum -a 256 -- "対象ファイル"`（macOS等）。Windowsでは `Get-FileHash -LiteralPath "対象ファイル" -Algorithm SHA256` 等、利用中の環境の同等機能を使う。空白を含むパスを引用する。シェルへ貼るパスや指示本文はコードとして評価せず、エディターまたはバイト保持できるファイル操作で扱う。

## 3. スキルと入口を配置する

原本overlay/skills/model-selection/を参照資料込みで、決定したスキル配置先へコピーする。配置した6ファイルのパス集合とSHA-256を原本と比較する。確認前のモデルIDやアカウント利用可否を有効と仮定しない。

次の管理ブロックを入口へ追加する。内部にはoverlay/instructions/model-routing.mdの本文全体を実際にコピーし、その末尾に、配置を確認したSKILL.mdの絶対パスを `model_selection_skill: ` に続けて一行記載する。山括弧の説明をそのまま展開しない。管理リポジトリや上流キャッシュのパスを読込先にしない。

```text
<!-- independent-model-routing:begin -->
（model-routing.mdの実際の本文全体）
model_selection_skill: （配置済みSKILL.mdの確認済み絶対パス）
<!-- independent-model-routing:end -->
```

入口の既存部分をバイト単位で保持する。終端改行がなければ、区切りの改行を追加部分の先頭に含めて保存する。管理部分の改行はLFでよいが、既存CRLF／BOMを変換しない。バイトを保持できないエディターでの全体再保存は避ける。初回は保存した原ファイルと追加前部分を比較する。コピーした本文は原本と一致し、相違は配置先bindingだけにする。

Localプロファイルでinstructions形式を選ぶ場合は、Agent Customizationsが提示する形式に従い、全体適用が必要ならapplyTo等の自動取り込み条件を確認する。見つかるだけで自動取り込み済みとしない。既存の適用条件や利用者ルールを管理ブロックのために破壊しない。

配置後の入口を読み、説明用プレースホルダーが残らないこと、binding先のファイルが開けること、6資料の相対リンクが成立することを確認する。リンクを置くだけでは入口やスキルの読込は保証されない。

## 4. 新しい会話で確認する

1. 選択中harness、本体と入口のソース、方針版、選択スキルのソースを確認する。管理画面に名前が見えることと、要求へ取り込まれたことを分ける。
2. 小さな読み取り依頼を行い、入口の実体が取り込まれ、配置済みSKILL.mdが読まれた要求内容／履歴を確認する。
3. 利用可能な正確な2モデルID・アカウント許可・容量・推論設定を確認し、同じ読み取り作業を正式なモデル指定で実行する。独立した実効情報を記録する。
4. 通常の最終レビュー、高リスク適性、指定拒否、Auto／上書き、未対応contextを対応するケースで確認する。架空fixture IDは実行しない。
5. 実効ID・設定が観測できなければunknown、当該受入はunverified。モデルの自己申告で補わない。3方式を個別判定し、揃うまで全体移行完了としない。

モデル指定は呼出し単位の正式引数を優先する。それがない場合だけ環境ガイドに従い、固有名independent-routing-<runtime>-<model-key>のworkerを登録する。個人CLI/Copilotは~/.copilot/agents/、プロジェクトは.github/agents/、Local個人はUIが提示する場所を確認する。確認済みIDを使い、レビューは読み取り専用、実装は必要な編集・テストだけを許可する。子へ必要な規約をbrief等で渡し、再委譲ツールを外して実効性を確認する。未確認フィールド・placeholder入り定義は有効化しない。

## 5. 更新する

まず前回の所有記録と現在の管理部分・スキルファイル集合・workerを照合する。所有外の新規ファイルや管理部分の編集があれば、差分と理由を確認してから進める。自動で上書きしない。

所有部分が記録と一致する場合、新しい6ファイルを別の一時配置で比較・確認してから置換する。入口は保存した管理部分の完全一致を一意に確認し、そのバイト範囲だけを新しい本文とbindingへ置き換える。前後の利用者部分は現在のバイト列を保持し、古いファイル全体のバックアップで戻さない。変更前の所有部分と新しい所有ハッシュを記録し、新しい会話で確認する。同じ版の再導入は内容・所有記録が一致すれば何もしない。

本体更新では取得元・導入版・クライアント版を再確認し、互換性を未検証へ戻す。モデル方針・派遣・レビュー・修正上限・ヘルパーを読み、影響ケースを再実行する。無改変で解決できない競合は再現条件と試した方法を記録し、常設パッチへ自動移行しない。料金表は独立して更新し、本体の版変更だけを理由に候補データを再設計しない。

## 6. 解除と旧方式へ戻す

現在の管理部分が最後の所有バイト列と完全一致し、一意に見つかることを確認して、その部分だけを除去する。記録に含まれる追加先頭改行も除去する。初回にファイルが存在せず、解除後に空になった場合だけ、その入口ファイル自体を除去できる。解除後も利用者部分があればファイルを残す。

スキル・任意workerは最後の所有パス集合とハッシュが一致した場合だけ所有ファイルを除去する。所有外ファイルや編集済みファイルがあれば停止し、利用者と差分を解消する。親ディレクトリは空で自分が作成した場合だけ除去し、~/.copilot/全体、他スキル、公式本体、全体設定を消さない。既存部分の最新内容が残ったことを確認する。

旧改変版はGit保存コミット4792d5eから別の一時ディレクトリへ取り出せる。戻す場合は新しい入口とスキルを解除し、同じ環境で公式版が同時に読み込まれないように利用対象を切り替えてから、旧版を認識先へ戻す。切替は利用者の既存設定を保全して行い、公式版と旧改変版の混在を復元成功としない。

## 7. 導入記録のひな形

```json
{
  "routing_revision": "2026-11-11.1",
  "source_commit": "<実際に使用した独自レイヤーのcommit>",
  "runtime": "<確認したharness>",
  "instruction_path": "<ローカルの正確な配置先>",
  "instruction_existed": true,
  "original_backup": "<バイト保存先>",
  "original_sha256": "<元ファイルのSHA-256>",
  "managed_bytes_backup": "<挿入した全バイトの保存先>",
  "managed_sha256": "<追加先頭改行込みのSHA-256>",
  "skill_root": "<配置済みmodel-selectionのroot>",
  "owned_files": {"SKILL.md": "<SHA-256。ほか5ファイルも記録>"},
  "workers": {}
}
```

これは記録の説明用で、実行設定ではない。原本と展開先の対応、前回ハッシュ、所有物、復元元を記録できれば、同じ情報を既存のローカル管理形式で持ってよい。
