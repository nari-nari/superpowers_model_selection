# 独立モデルルーティングの導入・更新・解除

この手順は手動配置用。実行先は利用するPC／リモート環境であり、管理リポジトリのoverlay自体は自動ロードされない。公式本体と独自機能を別途導入する。実機受入前は試験配置として扱う。

## 1. 配置を決める

| 環境 | 共通入口 | 選択スキル |
| --- | --- | --- |
| VS Code Local・個人 | Agent Customizations → Instructions → Userで作成したプロファイル指示。実際の保存先を記録 | ~/.copilot/skills/model-selection/ |
| VS Code Copilot／CLI・個人 | ~/.copilot/copilot-instructions.md。既存内容に管理ブロックを追加 | ~/.copilot/skills/model-selection/ |
| Codex拡張・隔離試験 | 新規試験プロジェクトのAGENTS.md。セクション8を参照 | .agents/skills/model-selection/ |
| プロジェクト内 | 対応する.github/copilot-instructions.mdまたはAGENTS.md | .github/skills/model-selection/ |

Localの指示読込設定と選択中harnessを確認する。CLIはエディター設定を継承しない。個人・プロジェクト・プラグイン・管理者提供の全ソースを見て、旧改変本体、公式本体、model-selectionの同名重複を識別する。由来の不明なファイルを消さない。LocalとCLIの入口が別ファイルになる場合、同じ原本から展開し、同一ターゲットへ二重追加しない。

公式本体は公式READMEの該当環境の導入経路を使う。基準はv7.0.2、commit22f0b463e7a5e579904dd6211a520321035526f7。本体のプラグインキャッシュやskillsを編集しない。導入される版が異なる場合は互換性を未検証とし、更新手順で確認する。公式インストール手順が指定版を提供しない場合も、実際の版を偽って基準版と記録しない。

## 2. 既存内容と所有範囲を保存する

配置前に次の情報をローカルの導入記録へ保存する。記録／バックアップはスキル検出先・Git管理対象の外へ置き、認証情報や個人パスを共有文書へ転記しない。

- 方針版2026-11-11.2、該当契約の料金表版（Copilot: 2026-11-10.1、Codex: 2026-11-11.codex.1）、原本コミット、実行環境／クライアント版、本体ソースと版。
- スキル原本、スキル配置先、入口ファイルの正確な絶対パス。
- 単独で読める本手順書の配置先`setup_document`、SHA-256、自分が新規作成したか。個人配置の例は`~/.copilot/model-routing/model-routing-setup.md`、プロジェクト方式は`.github/model-routing/model-routing-setup.md`。これは列挙したスキルファイルと別の所有物として記録する。
- 入口が元から存在したか、編集前ファイル全体のバイト保存先とSHA-256。既存の改行・BOM・日本語を保持する。UTF-8（UTF-8 BOM可）以外の形式はバイト追記せず、当該環境の対応形式と保全方法を確認できるまで導入を保留する。
- 所有する全スキルファイルの相対パス・SHA-256一覧。未知の既存ファイルは所有物に含めない。
- 入口へ挿入する管理部分全体のバイト保存先・SHA-256。追加した先頭改行も所有部分に含める。
- 必要な場合だけ登録したworkerのパスとSHA-256。既存workerは別管理。

既存のmodel-selectionがあり、過去の所有記録がなければ新規配置を保留し、由来と既存利用を確認する。過去の所有記録がある場合は更新手順で扱う。入口の管理マーカーが片方だけ、2組以上、または記録なしで存在する場合も、追記せず衝突を解消する。

SHA-256の確認例は `shasum -a 256 -- "対象ファイル"`（macOS等）。Windowsでは `Get-FileHash -LiteralPath "対象ファイル" -Algorithm SHA256` 等、利用中の環境の同等機能を使う。空白を含むパスを引用する。シェルへ貼るパスや指示本文はコードとして評価せず、エディターまたはバイト保持できるファイル操作で扱う。

## 3. スキルと入口を配置する

原本overlay/skills/model-selection/の実ファイル集合を列挙する。現版はSKILL.mdと参照7資料の計8ファイルで、将来も件数を固定せず相対パス集合を記録する。参照資料込みで、決定したスキル配置先へコピーする。配置した全ファイルのパス集合とSHA-256を原本と比較する。確認前のモデルIDやアカウント利用可否を有効と仮定しない。

本手順書`docs/model-routing-setup.md`も決定した`setup_document`へそのままコピーし、ハッシュ一致と単独で開けることを確認する。既存ファイルが未所有なら上書きしない。配置済みの環境ガイドからはローカル導入記録の`setup_document`を辿る。管理リポジトリの外へコピーしてもリンクが壊れないよう、本手順書は関連原本の場所を末尾のテキストで案内する。

次の管理ブロックを入口へ追加する。内部にはoverlay/instructions/model-routing.mdの本文全体を実際にコピーし、その末尾に、配置を確認したSKILL.mdの絶対パスを `model_selection_skill: ` に続けて一行記載する。山括弧の説明をそのまま展開しない。管理リポジトリや上流キャッシュのパスを読込先にしない。

```text
<!-- independent-model-routing:begin -->
（model-routing.mdの実際の本文全体）
model_selection_skill: （配置済みSKILL.mdの確認済み絶対パス）
<!-- independent-model-routing:end -->
```

入口の既存部分をバイト単位で保持する。終端改行がなければ、区切りの改行を追加部分の先頭に含めて保存する。管理部分の改行はLFでよいが、既存CRLF／BOMを変換しない。バイトを保持できないエディターでの全体再保存は避ける。初回は保存した原ファイルと追加前部分を比較する。コピーした本文は原本と一致し、相違は配置先bindingだけにする。

Localプロファイルでinstructions形式を選ぶ場合は、Agent Customizationsが提示する形式に従い、全体適用が必要ならapplyTo等の自動取り込み条件を確認する。見つかるだけで自動取り込み済みとしない。既存の適用条件や利用者ルールを管理ブロックのために破壊しない。

配置後の入口を読み、説明用プレースホルダーが残らないこと、binding先のファイルが開けること、配布した全資料の相対リンクが成立することを確認する。リンクを置くだけでは入口やスキルの読込は保証されない。

## 4. 新しい会話で確認する

1. 選択中harness、本体と入口のソース、方針版、選択スキルのソースを確認する。管理画面に名前が見えることと、要求へ取り込まれたことを分ける。
2. 小さな読み取り依頼を行い、入口の実体が取り込まれ、配置済みSKILL.mdが読まれた要求内容／履歴を確認する。
3. 利用可能な正確な2モデルID・アカウント許可・容量・推論設定を確認し、同じ読み取り作業を正式なモデル指定で実行する。独立した実効情報を記録する。
4. 通常の最終レビュー、高リスク適性、指定拒否、Auto／上書き、未対応contextを対応するケースで確認する。架空fixture IDは実行しない。
5. 実効ID・設定が観測できなければunknown、当該受入はunverified。モデルの自己申告で補わない。3方式を個別判定し、揃うまで全体移行完了としない。

モデル指定は呼出し単位の正式引数を優先する。それがない場合だけ環境ガイドに従い、固有名independent-routing-<runtime>-<model-key>のworkerを登録する。個人CLI/Copilotは~/.copilot/agents/、プロジェクトは.github/agents/、Local個人はUIが提示する場所を確認する。確認済みIDを使い、レビューは読み取り専用、実装は必要な編集・テストだけを許可する。子へ必要な規約をbrief等で渡し、再委譲ツールを外して実効性を確認する。未確認フィールド・placeholder入り定義は有効化しない。

## 5. 更新する

まず前回の所有記録と現在の管理部分・スキルファイル集合・workerを照合する。所有外の新規ファイルや管理部分の編集があれば、差分と理由を確認してから進める。自動で上書きしない。

所有部分が記録と一致する場合、新しい全スキルファイルを別の一時配置で比較・確認してから置換する。入口は保存した管理部分の完全一致を一意に確認し、そのバイト範囲だけを新しい本文とbindingへ置き換える。前後の利用者部分は現在のバイト列を保持し、古いファイル全体のバックアップで戻さない。変更前の所有部分と新しい所有ハッシュを記録し、新しい会話で確認する。同じ版の再導入は内容・所有記録が一致すれば何もしない。

単独配置した手順書も前回の`setup_document`ハッシュを確認し、原本が変わった場合だけ置換・記録更新する。編集済みならそのファイルの更新を保留する。スキルと異なる版の手順を無断で残さず、互換性と差分を確認する。

本体更新では取得元・導入版・クライアント版を再確認し、互換性を未検証へ戻す。モデル方針・派遣・レビュー・修正上限・ヘルパーを読み、影響ケースを再実行する。無改変で解決できない競合は再現条件と試した方法を記録し、常設パッチへ自動移行しない。料金表は独立して更新し、本体の版変更だけを理由に候補データを再設計しない。

## 6. 解除と旧方式へ戻す

現在の管理部分が最後の所有バイト列と完全一致し、一意に見つかることを確認して、その部分だけを除去する。記録に含まれる追加先頭改行も除去する。初回にファイルが存在せず、解除後に空になった場合だけ、その入口ファイル自体を除去できる。解除後も利用者部分があればファイルを残す。

スキル・任意workerは最後の所有パス集合とハッシュが一致した場合だけ所有ファイルを除去する。所有外ファイルや編集済みファイルがあれば停止し、利用者と差分を解消する。親ディレクトリは空で自分が作成した場合だけ除去し、~/.copilot/全体、他スキル、公式本体、全体設定を消さない。既存部分の最新内容が残ったことを確認する。

単独手順書は解除手順を読み終えた後、自分が作成したファイルで前回ハッシュと一致する場合だけ除去できる。編集済み・未所有の手順書は保持する。記録・バックアップを残すかどうかは利用者が決める。

旧改変版はGit保存コミット4792d5eから別の一時ディレクトリへ取り出せる。戻す場合は新しい入口とスキルを解除し、同じ環境で公式版が同時に読み込まれないように利用対象を切り替えてから、旧版を認識先へ戻す。切替は利用者の既存設定を保全して行い、公式版と旧改変版の混在を復元成功としない。

## 7. 導入記録のひな形

```json
{
  "routing_revision": "2026-11-11.2",
  "source_commit": "<実際に使用した独自レイヤーのcommit>",
  "runtime": "<確認したharness>",
  "instruction_path": "<ローカルの正確な配置先>",
  "instruction_existed": true,
  "setup_document": "<単独で開ける配置済み手順書の絶対パス>",
  "setup_document_sha256": "<手順書全体のSHA-256>",
  "setup_document_created": true,
  "original_backup": "<バイト保存先>",
  "original_sha256": "<元ファイルのSHA-256>",
  "managed_bytes_backup": "<挿入した全バイトの保存先>",
  "managed_sha256": "<追加先頭改行込みのSHA-256>",
  "skill_root": "<配置済みmodel-selectionのroot>",
  "owned_files": {"SKILL.md": "<SHA-256。全配布ファイルを列挙>"},
  "workers": {}
}
```

これは記録の説明用で、実行設定ではない。原本と展開先の対応、前回ハッシュ、所有物、復元元を記録できれば、同じ情報を既存のローカル管理形式で持ってよい。

関連資料は取得した原本パッケージの`overlay/instructions/model-routing.md`、`overlay/skills/model-selection/SKILL.md`、`overlay/skills/model-selection/references/runtimes/`、`compatibility/superpowers.md`、`docs/superpowers/validation/independent-model-routing.md`を参照する。これらは原本内の場所であり、単独配置した本手順書からの相対リンクとは扱わない。

## 8. Codex拡張の隔離試験

対象はVS CodeのOpenAI Codex拡張。CopilotのLocal／Copilot harnessおよびCodex CLIとは別に判定する。今回ユーザーが確認した契約はChatGPT Plusだが、含有利用枠か追加クレジットかは未確認。料金表だけでは含有枠を計算できず、Copilot換算・API価格を代入しない。

### 試験フォルダの準備

1. `/private/tmp` 配下の新規フォルダを試験用に作り、その中で `git init` を実行する。既存フォルダを上書きせず、リモートを追加しない。管理リポジトリのworktreeとは別のフォルダにする。
2. 本手順§2～3に従い、入口は `AGENTS.md`、全スキルは `.agents/skills/model-selection/`、単独手順書はルートの `model-routing-setup.md` とする。入口本文は同じ原本の `overlay/instructions/model-routing.md`、bindingは試験フォルダ内の実在するSKILL.mdとする。原本を読み込むbindingにしない。
3. `fixture.txt` に `routing-fixture: codex-extension-v1` の1行と末尾LFを保存する。公式Superpowersは既存の正規導入の有効ソース・版を確認する。別版を自動で追加せず、同名重複や本体未認識は未検証の理由として記録する。
4. この試験のローカル所有記録は `.routing-local/ownership.json` とする。Git管理とスキル検出の対象外になるよう、新規の `.gitignore` に `.routing-local/` を含める。entry、スキルの相対パス集合、各SHA-256、setup_document、fixture、案内ファイル、自分が作ったGit管理外フォルダを記録する。個人パスを含む記録は共有資料へ転記しない。
5. `.routing-local/` の試験結果は所有配布物と別管理にし、更新・解除で削除しない。workerは正式指定引数がないと確認した場合だけ、当該版で認識を確認して `.codex/agents/` へ作る。placeholderを含む定義、未知のモデルID・フィールドは有効化しない。

### 最初にユーザーが行う操作

準備済み試験フォルダをVS Codeの「フォルダーを開く」で開き、Codex拡張で新しい会話を作る。親モデルの変更や個人設定の編集は不要。次の依頼は子を起動しない事前確認だけを行う。

```text
このフォルダでCodex拡張のモデルルーティングを検証します。まず事前確認だけを行い、子エージェントはまだ起動しないでください。
AGENTS.mdの入口とmodel_selection_skillの実在するbinding、配置済みSKILL.md、Codex用ガイド・カタログを読み、方針版2026-11-11.2を確認してください。ローカル所有記録は.routing-local/ownership.json、導入手順はmodel-routing-setup.mdです。
実際の指示取り込み／読込履歴、同名スキルと公式Superpowersの有効ソース・版、取得可能な稼働中の拡張／エンジン版、子のモデル・推論指定の正式スキーマ、アカウントで利用可能な2モデルの正確なID・容量・対応推論を確認してください。インストールファイル版や他チャットの許可リストで代用しないでください。
契約はChatGPT Plusです。含有枠か追加クレジットか、speed、呼出し単位の使用量の観測方法も分かる範囲で記録してください。モデル名・容量・設定・費用を推測せず、不明はunknownとしてください。認証情報・全体設定ファイル・無関係なログは出力しないでください。
結果を.routing-local/preflight.mdに保存し、取得できた証拠と次に必要な情報を短く報告してください。編集はこの結果ファイルだけとし、fixtureと設定は変更しないでください。
```

上記結果と必要ならVS Codeの拡張画面の稼働版を確認してから、2モデルの同一fixture試験へ進む。正式な経路が確認できない場合、子呼出しを実行しない。この手順は事前確認と結果保存を依頼するもので、ツールの存在や証拠の公開を保証しない。事前確認のために正式スキーマを取得できなければunknownを保持する。

### 実行・更新・解除

2モデルが利用可能で容量・正式な指定経路を確認したら、同じfixture読み取りを各1回、順番に実施する。使用量は呼出し前後から採取する。費用選択ができない場合は `selection_mode: fixed-capability-probe` とし、unknown費用を保つ。実効モデル・推論・contextは拡張の子スレッドやネイティブログで独立確認する。初回の拒否試験は安全な1回まで。未再現のfallback等を合格にしない。

更新・解除は§5～6の所有部分照合に従う。全配布パスを列挙し、変わった所有ファイルと未所有物は保持する。事前確認や実機試験が未完了なら試験配置を保持して再開に使う。終了時も `.routing-local/` の結果とバックアップは残し、解除後の新しい拡張会話で入口が取り込まれないことを確認する。Gitリポジトリ全体・公式本体・個人設定の削除は解除に含めない。
