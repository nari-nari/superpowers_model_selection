# Model selection scenarios

架空の料金、実モデルではない。fixture ID は実際の派遣に使用しない。判断だけを返す読み取り専用シミュレーション。

## 行動入力

期待記録の項目名は共通インターフェースを使い、正しい文章の完全一致では採点しない。

| 対象AC | 入力として与える条件 | 必須の判断・記録 |
| --- | --- | --- |
| AC02・AC03 | F02 の料金、1ファイルの認証処理と、別ケースの通常リスク最終レビュー | 認証はaを適性で除外してb。通常レビューはaを比較対象から落とさない |
| AC04 | 高リスク箇所に触れない単純な表示修正だけが再レビューに残る | 通常リスクへ再評価し、aを選べる |
| AC08 | aの基本経路0.11 USD、追加修正0.11、引き継ぎ0.02、bの基本経路0.204、成功確率・実績なし | 基本経路はa。修正経路0.24で逆転することを別記し、確率加重値を作らない |
| AC09・AC12 | aは指定時に拒否、bは許可。別ケースでは要求aに対して実効bというツール結果 | 前者はbで再比較。後者は不一致と費用差を記録し、適性・許可範囲を再確認 |
| AC10 | verified_at=2026-11-10、比較日2026-12-10と12-11、取得不能 | この計画では年齢が30日を超えたら期限超過と定義。前者は範囲内、後者は古さを一度通知して暫定扱い |
| AC11 | Local の許可候補はaだけ、bの指定が費用階層で拒否 | 通常作業はaへ再選択。bだけが適格な高リスク作業は当該派遣を保留 |
| AC12・AC13 | モデル・context の実効値が取得不能、子のcontext設定引数なし、予測ピーク160,001 | 実効はunknown、親切替なし。通常上限の80%超として情報整理を先に検討し、設定適用を捏造しない |
| AC14 | 許可・適格候補はbのみ、F02の入出力、明示残予算20 credits | 20.4 creditsで超過。代案を検討し、解決しなければ当該派遣だけ確認対象 |
| AC15 | 評価対象bの同一variantを反復中、通常の価格比較ではaが安い | bと設定を固定し、途中でaに変更しない |
| AC16・AC19 | 会話圧縮後に方針パス・catalog_revision・前回記録のみが残り、actual_cost取得不能 | 参照から復元、実費unknown、追加の見積もり担当を派遣しない |
| AC20 | テストツールの認証失敗、別ケースではfix round 3/5の後に推論不足が判明 | 認証障害だけでは昇格しない。4/5は新規担当で能力を再評価し、最大5回を維持 |


## AC索引

| ID | ケース | 期待結果 |
| --- | --- | --- |
| AC01 | 局所的で検証可能な実装 | 適性を満たす具体的な候補を料金で比較。最高能力の固定選択をしない |
| AC02 | 小さな認証・並行処理の差分 | ファイル数によらず領域適性を要求し、未確認の通常作業用候補を除外 |
| AC03 | 最終レビュー | 全体の関係とリスクに対応した候補を比較。`most capable` だけを根拠にしない |
| AC04 | 小さい修正の再レビュー | 修正範囲に応じて安価な候補へ変更できる |
| AC05 | 長文料金の閾値直前／一致／直後 | 比較条件とモデルごとの適用範囲を正しく扱い、価格順位の逆転を検出 |
| AC06 | 入力が安いが出力が高い候補 | 出力量を含む総額で比較し、入力単価だけで決めない |
| AC07 | キャッシュ率不明、書き込み料金あり | 根拠のない割引やゼロ料金を置かず、課金の重複計上も避ける |
| AC08 | モデル変更と再試行 | 引き継ぎと修正の追加費用を考慮し、成功確率を捏造しない |
| AC09 | 未掲載／廃止／組織で禁止されたモデル | 実行候補から除外し、未指定による暗黙の継承で成功扱いにしない |
| AC10 | 料金表の期限超過、取得不能 | 古さと暫定見積もりを一度通知。繰り返し取得や未知価格の補完をしない |
| AC11 | VS Code Local の費用階層による拒否 | 利用可能候補で再選択し、親モデルを無断で変更しない |
| AC12 | VS Code Copilot／CLI の設定上書き・Auto・変換 | 要求と実効を区別。不適用を検出または未確認と明記 |
| AC13 | 子ごとのコンテキスト指定がない環境 | 入力を整理し、設定できたと偽らない。ラッパーを追加しない |
| AC14 | 明示予算を超える見積もり | 代案を検討し、当該派遣だけを確認対象にする |
| AC15 | スキルのモデル比較テスト | variant 間で対象モデルと設定を固定し、モデル別に記録 |
| AC16 | 反復派遣と圧縮後の再開 | 方針と一覧の版を再利用・復元し、見積もり担当の追加派遣をしない |
| AC17 | 35項目の移行確認 | 全項目を更新または非適用と説明。古い選択命令を実行経路に残さない |
| AC18 | 実際の環境で2候補を選択 | VS Code の各対応方式と CLI で、要求モデル・実効結果・確認できない項目を記録 |
| AC19 | 最適性や実測が不明 | 節約保証や実費の取得を主張せず、不確実性を表示 |
| AC20 | ツール環境の失敗 | 不要なモデル昇格をせず、修正ループの既存上限を維持 |

## 評価方法

原文スキルを文脈として読み、model_requested、model_effective、context_requested、context_effective、estimate_creditsと理由を返す。controlには新しいルールを入れない。variant間で評価モデルとeffortを固定する。各サンプルは独立したfresh context。主要3ケースはcontrol/changed各5回。自己申告を実効値の証拠にしない。実ログはvalidation文書へ記録し、シミュレーションとCopilot実機を区別する。
